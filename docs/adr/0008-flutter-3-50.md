# ADR 0008: Flutter 3.50.1 / Dart 3.14.0

- Status: accepted
- Date: 2026-11-24
- Decided by: PM, 2026-11-24 ("Approve, all A"; deck `docs/slides/flutter-3-50.html`, decisions F1–F3 all A)
- Supersedes: the Flutter 3.44.6 / Dart 3.12.2 version in ADR 0001 (ADR 0001's choice of Flutter desktop stands)

## Context

The pinned Flutter 3.44.6 / Dart 3.12.2 blocks the dependency updates in M1.10: sqlite3 >= 3.6.0, window_manager >= 0.6.0 and tray_manager >= 0.7.0 need Flutter 3.50 / Dart 3.14. Flutter 3.50.1 is the current stable release (2026-11-20). It also fixes the macOS 27 `lipo` failure that forced `ARCHS = arm64` in M1.9b. In 3.50 the in-framework Material and Cupertino libraries are deprecated in favour of the `material_ui` and `cupertino_ui` packages.

## Decision

We will build Kusunga with Flutter 3.50.1 (Dart 3.14.0) on every machine and in CI, and move the app's Material imports to `material_ui`. The Dart language version in `pubspec.yaml` stays `^3.12.2` in this change; M1.10b raises it.

## Consequences

- M1.10b can update sqlite3, window_manager and tray_manager.
- The Mac release build no longer needs `ARCHS = arm64` to work around the lipo bug; Apple-silicon-only stays a product choice (decision D3).
- One more package (`material_ui`, BSD-3-Clause, Flutter Authors) is in the app and on the licences page.
- Every Flutter version pin (CI, CLAUDE.md, `docs/licences.md`, docs) changes together; a `test/ci` check keeps them equal.
- Going back means reverting the change and using Flutter 3.44.6 again; no data step.
