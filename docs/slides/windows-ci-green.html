Your data

Delete everything works on Windows

Evidence

  • On GitHub's Windows machine, the tests that run Delete everything to the end passed and check the database file is gone
  • The app closes the database before deleting; the log and export files are never left open

Developer: about 85% sure. A Windows QA run confirms it in M1.9d.

One gap

Nothing stops two copies of Kusunga running on Windows. The second copy keeps the database open, so Delete everything would leave it behind. The user sees the existing "couldn't be removed" message; nothing is hidden. Decision W3.

The fix

Small test fixes, then the first Windows build

Tests and config

  • Close the database before each test deletes its folder
  • Read files with any line ending; use Windows-safe paths
  • Store text files with Unix line endings (.gitattributes)
  • Mac: check line order instead of a 90% rate

Windows build (risk)

  • The Windows-only code has never been compiled with Microsoft's compiler, and warnings count as errors
  • CI will now build even when tests fail, so one run shows both
  • Build errors are fixed in this item; any change to app behaviour comes to you first

How we check it

On branch fix/windows-ci with a pull request: both CI jobs green, the Windows build succeeds, and check.sh passes on the Mac. Then tester, reviewer and QA as usual. No new data, no secrets in CI.
