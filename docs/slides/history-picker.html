Problem and users

Today it takes five steps to paste from history

Who

Anyone typing in any app on Mac or Windows who copied something earlier.

The job they are doing

Paste an older copy without leaving the app they're in.

Today's pain

Open Kusunga, find the item, click Copy, go back, press ⌘V.

Success measure

Shortcut to pasted in under 3 seconds, and never into the wrong app.

Scope for this step

The picker, paste, and a safe fallback

In M1.3

  • Shortcut opens a picker over any app (you can change it)
  • Type to search; Enter or ⌘1–9 pastes
  • Keyboard only, VoiceOver and Narrator
  • If pasting isn't allowed: copies it and says "press ⌘V"
  • "Open picker" in the menu-bar menu

Not in this step

  • Snippets in the picker: M1.4 · Typed shortcuts: M1.5
  • Hide previews while screen sharing, trigger: ≥ 5 beta users ask or M2 vault ships
  • Mac App Store version, trigger: ≥ 50 requests
  • Typo-tolerant search, trigger: ≥ 10 "can't find" reports

All slides apply.

Options

How to ship the Mac app, and how to build the picker

Mac: direct download, sandbox kept on (A)

  • Paste and typed shortcuts work, no App Store review risk
  • Data stays where it is; sandbox still limits damage
  • We handle updates ourselves later

Mac: App Store (B)

  • Easy to find and install
  • Apple has rejected clipboard managers that paste for you; we might have to make you press ⌘V
  • Typed shortcuts at risk too

Recommendation

Direct download (A), notarised by Apple, with the sandbox on (ADR 0003). The picker reuses Kusunga's one window in a small "picker mode", so there's still only one connection to your encrypted history.

Security

Paste only into the app you were using

Trust boundaries

  • Other apps receiving our ⌘V
  • The macOS keystroke permission
  • The clipboard after we paste
  • Screen sharing while the picker shows

Abuse cases

  • An app grabs focus to receive the paste
  • An app fakes Kusunga's "this is mine" marker
  • Someone watches the picker on a shared screen
  • An admin window is targeted

Mitigations

  • Paste only after confirming your app is in front, else copy only
  • Marker only moves items already in history
  • One-line previews; nothing until you press the shortcut
  • Never send keys to admin windows (Windows)

Kusunga never asks for the permission to read other apps' screens. Apple DTS: posting key events works in the sandbox (Developer Forums 820594, March 2026).

Decisions needed

4 decisions for you

1. How to ship the Mac app

Options: direct download (notarised, sandbox on), or Mac App Store

Recommendation: direct download, so pasting for you works without App Store risk

2. Default picker shortcut

Options: ⌘⇧V / Ctrl+Shift+V (familiar, replaces "paste as plain text"), or ⌥⌘V / Ctrl+Alt+V (free, less familiar)

Recommendation: ⌘⇧V / Ctrl+Shift+V, because Kusunga pastes plain text anyway and you can change it

3. After pasting, what's on the clipboard?

Options: the pasted item stays on the clipboard, or Kusunga puts back what was there before

Recommendation: the pasted item stays — simpler and what most people expect

4. Approve the design and screen spec

Options: approve, or tell me what to change

Recommendation: approve, so the developer can start
