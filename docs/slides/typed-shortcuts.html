Typed shortcuts

Type a short code such as ;email in any app, and Kusunga replaces it with your saved snippet.

Use the arrow keys to move between slides · Print to save as PDF

Problem and users

Pasting the same snippet many times a day still takes several keys

Who

People who paste the same few things often, such as their email address, phone number or a meeting link.

The job they are doing

Filling in forms, replying to emails and chats, without leaving the keyboard.

Today's pain

With M1.4 this takes 4 to 6 keys: open the picker, switch to Snippets, search, then Enter.

Success measure

The typed code is replaced within 0.15 s. Setting a shortcut takes under 15 s. Kusunga never replaces anything in a password field or an ignored app.

Plan item M1.5 (docs/PLAN.md). Details: docs/design/typed-shortcuts.md, docs/ui/typed-shortcuts.md, ADR 0004.

Scope for this phase

Shortcuts on snippets, one switch, and a list of apps where Kusunga stays quiet

In this phase

  • An optional shortcut on each snippet (2–32 characters, no spaces), checked as you type
  • Shortcuts work in every app, except password fields, ignored apps, Kusunga itself and Windows admin windows
  • One switch, a status line, and an ignored-apps list that starts with the common password managers
  • On Mac, a plain explanation before the Input Monitoring permission prompt
  • Shortcuts shown and searchable in the list and the picker

Deferred (Later lines with triggers)

  • Undo a replacement with Backspace, trigger: ≥ 10 requests or ≥ 5 reports of an unwanted replacement
  • Per-app shortcut sets, trigger: ≥ 10 requests
  • Chinese, Japanese and Korean input and dead keys, trigger: ≥ 5 reports
  • Windows admin apps, trigger: ≥ 5 reports
  • On-screen keyboards and remote desktop, trigger: ≥ 5 reports

No slides deleted. Placeholders such as {date} are already a Later line from M1.4.

Options

Where Kusunga notices what you type

Option A: in the small native part

  • The keys stay in a 32-character buffer in the Mac or Windows code. Only "snippet 3 matched" reaches the rest of the app
  • Nothing you type can reach a log or the main app code
  • The matching code is written twice, once for Mac and once for Windows. About 1.5× the effort

Option B: in the shared app code

  • One copy of the matching code
  • Every key you type in every app passes into the main app. On Windows that includes passwords
  • Slower for each key, and Windows can switch off a slow keyboard hook

Recommendation

Option A, because then the promise "Kusunga never saves or sends what you type" is simple and true (ADR 0004).

Security

No other program should be able to trigger or read a snippet

Trust boundaries

  • Keys typed in other apps, including passwords
  • Keys sent by other software
  • The keys and clipboard text Kusunga sends into other apps

Abuse cases

  • Another program types ;bank into its own window to get your bank details
  • Malware reads Kusunga's memory or logs for recent keys
  • A shortcut fires in a Windows password field

Mitigations

  • Keys sent by software are ignored (decision 5)
  • 32 characters at most, for 5 s, never logged; no crash reports
  • On Windows, the password-field check doesn't fire when it can't tell
  • Pasted snippets are marked so other clipboard managers don't save them

Mac password fields turn on "secure input", which hides keys from Kusunga (ADR 0003). Windows has nothing like it, so Kusunga checks the field when a shortcut matches.

Plan and how you'll check it

Built in four steps, Mac first

1 Shortcut field and data update→ 2 Key watching and matching, Mac then Windows→ 3 Replacing the code with the snippet→ 4 Switch, status and ignored apps

How we will check it

  • Automated: tests for each rule (buffer size, the 5 s clear, every skip case) and a check that nothing typed is logged. Evidence in docs/qa
  • QA on your Mac in the test profile: replacement in TextEdit and a browser; nothing in a password field, Terminal secure entry or an ignored app. Screenshots and videos
  • What only you can check: granting Input Monitoring in System Settings, and VoiceOver

Decisions needed

6 decisions for you

1. When does a shortcut fire?

Options: A, as soon as it's typed, so no shortcut may start another one; or B, after the next space or Enter

Recommendation: A, because it's fastest and the editor checks the rule

2. What's on the clipboard afterwards?

Options: A, what was there before (put back after 0.5 s); B, the snippet, as with the picker; or C, type it key by key

Recommendation: A, because a shortcut shouldn't quietly replace what you copied

3. On or off for a new user?

Options: A, off until you turn it on; or B, on once a shortcut exists and permission is given

Recommendation: A, because watching the keyboard should be a clear choice

4. Ignored-apps list now?

Options: A, build it now with password managers preset (M1.6 reuses it); or B, password fields only now

Recommendation: A, because it's in the plan and serves M1.6 too

5. Keys sent by other software?

Options: A, ignored; or B, accepted (on-screen keyboards, remote desktop)

Recommendation: A, so no other program can pull out a snippet

6. When is the privacy assessment (DPIA) done?

Options: A, in the short DPIA already planned for M1.9, before the beta; or B, a short one now

Recommendation: A, because nothing leaves the device and there are no outside users before M1.9
