Move to Flutter 3.50.1

Nothing changes for users. It unlocks the package updates, including the newer encryption library.

Use the arrow keys to move between slides · Print to save as PDF

Problem and users

Our Flutter version is too old for the package updates

Who

The team building Kusunga, and everyone who uses it through safer, current dependencies.

The job

Keep sqlite3 (with its encryption library), the window and the tray packages up to date.

Today's pain

None of the three updates installs on Flutter 3.44.6. They all need Flutter 3.50.

Success measure

All checks and both CI jobs pass on 3.50.1, with no change users can see.

Flutter 3.50.1 is the current stable release (2026-11-20, Dart 3.14.0). Design note: docs/design/flutter-3-50.md · ADR 0008 (proposed).

Scope

Only the Flutter move. The packages come next, in M1.10b

In this item

  • Build and test with Flutter 3.50.1 on Mac, Windows and CI
  • Move the screens' design library to its new home (material_ui): a mostly automatic rewrite of about 118 files' imports
  • Change every place that names the Flutter version, together

Not in this item

  • sqlite3, window_manager, tray_manager updates: M1.10b, right after
  • Intel Mac build: Later line, trigger: at least 1 tester or user asks for one (decision F3)

Data and privacy slide removed: no personal data, store or format changes in this item.

Options

Two ways to do it

Option A: new folder, migrate now

  • Flutter 3.50.1 goes in its own folder; your 3.44.6 and your other projects are untouched
  • The deprecated design library is replaced now, so the check stays strict
  • Bigger change set, but mechanical: one developer round

Option B: upgrade in place, migrate later

  • Smaller change now
  • Changes the Flutter your other projects use
  • Turning off a warning can hide other real warnings: a weaker check

Recommendation

Option A, because it keeps your other projects safe and keeps the check as strict as it is today.

Security

New code comes from two places, both pinned

Trust boundaries

  • The Flutter 3.50.1 download from GitHub
  • The new material_ui package from pub.dev

Abuse cases

  • A look-alike package gets pulled into the build
  • A changed Flutter release tag

Mitigations

  • material_ui is published by flutter.dev; the lock file pins its hash; the reviewer checks the publisher
  • We install by tag and log its commit; CI pins the same version

No change to what the app stores, sends or encrypts.
