Your data: export and delete

Save your snippets (and history, if you choose) to a file, bring them back, and make Kusunga forget everything.

Use the arrow keys to move between slides · Print to save as PDF

Problem and users

Your data is locked inside one encrypted file on one computer

Who

Anyone moving to a new computer, wanting a copy of their snippets, or wanting Kusunga to forget them.

The job they are doing

Taking their snippets with them, and being sure that "delete" really means gone.

Today's pain

There is no way to copy snippets out. Clear history keeps snippets, settings and the key. There is no way to remove everything.

Success measure

Export in 3 actions. Import never changes what you have. Delete everything leaves nothing readable, including the key.

Plan item M1.8 (docs/PLAN.md). Resized from small to large: export moves personal data out of the encrypted file, import reads a file Kusunga doesn't control, and Delete everything removes the key. Details: docs/design/your-data.md, docs/ui/your-data.md.

Scope for this phase

A "Your data" section at the end of Settings

In this phase

  • Export… snippets and settings to a JSON file; history only if you tick it
  • Import… that file: adds, never overwrites
  • Delete all history… (today's Clear history, now in Settings too)
  • Delete everything…: history, snippets, settings, ignored apps, log and the key; then Kusunga quits

Deferred (Later lines with triggers)

  • Password-protected export, trigger: ≥ 5 beta requests
  • Import from other clipboard apps (Paste, Maccy, Ditto), trigger: ≥ 10 beta requests naming one app
  • Sync between devices: M3

How it works

Delete everything removes the key first

1 Stop capture, close the file→ 2 Delete the key→ 3 Delete files and log→ 4 Login item off, quit

Why the key first

Once the key is gone, the history file can't be read by anyone. If a file can't be removed, it is still unreadable. If the key can't be deleted, nothing is deleted and you are told.

Import is checked first

Kusunga checks the whole file against its own rules before changing anything, and imports in one step. A damaged or crafted file changes nothing.

New for the app: the Flutter team's file_selector package for the Save and Open dialogs, and a Mac permission to read or write only the file you pick.

Plan and how you'll check it

Built in three steps

1 File format, export and import→ 2 Delete everything and the key delete→ 3 The Your data section

How we will check it

  • Automated: export then import gives the same data; crafted files are refused; the delete order; every dialog state
  • QA on your Mac in the test profile: export, import into the test profile, and Delete everything on the test profile's own data only

Decisions needed

6 decisions for you

1. Is the export encrypted?

Options: A, a plain JSON file with a clear warning; B, encrypted with a password you type; or C, plain for snippets, with a password needed to include history

Recommendation: A, as the plan says, with a password option later. This also approves the file_selector package and the Mac file permission

2. History in the export by default?

Options: A, off, with an "Include history" tick box; or B, on

Recommendation: A, the private choice by default

3. What does import do?

Options: A, merge: add, skip exact copies, never overwrite; B, replace everything; or C, ask each time

Recommendation: A, so nothing is lost by surprise

4. What does "Delete all history" do?

Options: A, today's Clear history, which keeps snippets, settings and the key, plus shrinking the file; or B, also deletes the key

Recommendation: A. Deleting the key would lose snippets too; Delete everything does that

5. Settings and ignored apps in the export?

Options: A, yes, used on import only if you tick "Also use the settings in this file"; or B, snippets and history only

Recommendation: A, as the M1.7 deck promised

6. After Delete everything

Options: A, turn launch at login off and quit; or B, stay open on an empty Kusunga

Recommendation: A, so nothing stays in memory and nothing starts again at login
