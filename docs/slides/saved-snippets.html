Save what you paste often, and never lose it

Your phone number, email, address and links, saved once, in your own order, and pasted from the same ⌘⇧V picker.

Use the arrow keys to move between slides · Print to save as PDF

Problem and users

History forgets; some things you paste every day

Who

Anyone who types the same few things again and again: a phone number, an email, an address, a meeting link.

The job they are doing

Paste a fixed piece of text in a few keys, without retyping it or hunting through history.

Today's pain

History keeps only the newest items. Your phone number drops off after 200 copies, and you type it again.

Success measure

Save a snippet in under 20 seconds. Shortcut to pasted in under 3 seconds. Snippets are never lost.

Plan item M1.4. Design: docs/design/saved-snippets.md · Screen spec: docs/ui/saved-snippets.md.

Scope for this step

Snippets you manage, in their own picker tab

In M1.4

  • New, edit, delete (with Undo) and reorder snippets: name, type, text
  • Reorder without dragging: Move up / Move down, or ⌥↑ / ⌥↓
  • "Save as snippet" on any history item
  • A Snippets tab in the picker; ⌃Tab switches tabs
  • The history limit and Clear history never touch snippets
  • Keyboard only, VoiceOver and Narrator

Not in this step

  • Typed shortcuts like ;email: M1.5 · Bank and card vault: M2 · Export: M1.8
  • Placeholders like {date}, trigger: ≥ 10 beta requests
  • Folders or tags, trigger: median user has > 50 snippets
  • "Most used" order, trigger: median user has > 30 snippets

All slides apply.

Options

Where to keep your snippets

A: In the same encrypted file as history

  • One key, one file, one keychain prompt
  • Reuses every safety check from M1.2
  • "Delete everything" removes one file

B: A second encrypted file

  • Survives a damaged history file
  • Two keychain items, two prompts on test builds
  • Twice the start-up error handling; overlaps the M2 vault

Recommendation

A. Snippets go in a new table in your existing encrypted history file. It's easy to move later if we ever need to, so no architecture decision record is needed.

Security

Nothing becomes a snippet unless you press Save

Trust boundaries

  • Text you type or pin into a snippet
  • History items, which can come from any app
  • The clipboard after a snippet is pasted
  • Screen sharing while the picker shows

Abuse cases

  • An app fakes Kusunga's "this is mine" marker
  • An app reads the clipboard after you paste your address
  • Someone watches the picker on a shared screen
  • Huge or odd text in the editor

Mitigations

  • Kusunga recognises its own pastes by a number no other app can fake
  • Same as any paste today; the M2 vault clears the clipboard
  • One-line previews; nothing until the shortcut
  • Same limits and checks as history

No new permission. No content, names or types in logs: codes only, from the fixed list added in M1.3.

Decisions needed

5 decisions for you

1. Does pasting a snippet also add it to history?

Options: no, or yes like any copy

Recommendation: no — it's already saved, and this keeps personal details in one place

2. Pinning a history item: copy or move?

Options: copy (stays in history), or move (removed from history)

Recommendation: copy — nothing disappears unexpectedly

3. Which tab does the picker open on?

Options: History always, the last one you used, or Snippets always

Recommendation: History always — one predictable shortcut; ⌃Tab is one key away

4. Bank and card details before the vault

Options: allow with a short note that the vault is coming, allow with no note, or detect them and warn

Recommendation: allow with a short note; detection belongs to the vault design

5. Approve the design and screen spec

Options: approve, or tell me what to change · Recommendation: approve, so the developer can start

Assumed unless you say otherwise: at most 1,000 snippets; names can repeat; Clear history keeps snippets.
