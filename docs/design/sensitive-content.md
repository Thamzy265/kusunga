# M1.6 Sensitive-content protection — design note

Date: 2026-11-10 — Size: large — personal data (which app a copy came from, and the user's choice to stop recording) and new decisions inside clipboard capture on Mac and Windows — Phase: MVP — Status: approved by PM 2026-11-10 ("Approve as recommended": option A, D1–D5 all A)

## Context

Plan item M1.6 (`docs/PLAN.md`):

- AC1: an app ignore list (preset with common password managers and banking apps) stops capture from those apps.
- AC2: "Pause history" for 15 min / 1 h / until resumed, from the tray/menu bar.

What exists today:

- **Capture.**
  - Mac: polls `NSPasteboard.changeCount` every 250 ms (`macos/Runner/ClipboardWatcher.swift`).
  - Windows: listens for `WM_CLIPBOARDUPDATE` (`windows/runner/clipboard_bridge.cpp`).
  - Both skip copies marked secret (M1.2: Concealed, Transient, AutoGenerated on Mac; ExcludeClipboardContentFromMonitorProcessing and related formats on Windows) without reading the text.
  - Dart (`lib/history/history_service.dart`) saves the rest.
  - Capture does not know which app a copy came from.
- **Ignore list.** M1.5 built the `ignored_apps` table (app_id, display_name, preset), seeded with five Mac and four Windows password managers. Typed shortcuts are its only user so far. M1.5 decision D4 says M1.6 reuses it. Its UI is inside the Typed shortcuts section of the Snippets tab.
- **Tray.** The tray / menu-bar icon (`tray_manager` plugin, `lib/tray/tray_service.dart`) has Open picker, Open Kusunga and Quit.
- **Pause.** There is no history pause. Banners in the History tab (`HistoryBanner`) show states such as memory only.

## Requirements and non-goals

- Functional:
  - A copy made in an app on the ignore list is not added to history. Its text is never read.
  - The ignore list is preset with common password managers, and the user can add or remove apps (as in M1.5).
  - "Pause history" for 15 minutes, 1 hour, or until resumed, from the tray / menu bar and from inside the app. While paused, no copy is added to history and no text is read.
  - The tray menu shows "Resume history" while paused. The tray tooltip and a History banner say history is paused and until when.
  - A timed pause ends on its own at the right wall-clock time, also after the Mac or PC slept.
- Non-functional:
  - The source app is worked out in native code and never crosses the Flutter channel, is never logged and never stored. Only the list the user chose is stored (it already is, encrypted).
  - Checking the source adds under 5 ms per copy.
  - Logs hold codes only (`captureSkippedIgnoredApp`, `capturePaused`, `captureResumed`), never app names or text.
- Non-goals (each has a Later line below):
  - Ignoring a website or a browser tab. Banking in a browser is covered by secret markers and by Pause, not by the app list.
  - Detecting card numbers or passwords by their content.
  - Separate lists for history and typed shortcuts (see decision D1).
  - Per-app settings beyond on or off.

## Top 3 qualities

| Quality | Target | How we check it |
|---|---|---|
| Privacy | A copy from an ignored app, or made while paused, is never read: its text never leaves the OS clipboard into Kusunga's memory, channel, log or file | Native unit tests of the skip decision; a channel guard that the clipboard event carries no app field; QA real flow with an ignored app and with Pause; log-code test |
| Correctness | The source app is right for a normal copy (keyboard or menu in the front app) on both systems; a pause ends at its wall-clock time ±1 s, including after sleep | Native unit tests of the source rules with fakes; Dart tests of the pause clock; QA timing check |
| Clarity | The user can always see that history is paused, until when, and can resume in one action, from the tray or the app | UI spec states; QA screenshots; accessibility check |

## Estimate

Trivially small. A person copies at most a few times a minute. The list holds at most 100 apps. One lookup per copy.

## Data

- **No new table.** The `ignored_apps` table from schema v4 is used as is, for both history and typed shortcuts (decision D1).
- **New setting** in the existing `settings` table: `history_paused_until` (INTEGER).
  - 0 means not paused; -1 means paused until resumed; any other value is the end time in ms since 1970 (UTC).
  - It is added to `HistoryStore.storedSettingKeys`.
  - It is stored in the encrypted file, so it survives a restart (decision D3).
- **Schema v5**, expand only, inserts any new verified preset rows (decision D2). For example, on Mac: LastPass, Enpass, NordPass, Proton Pass, Dashlane. On Windows, the same names' exe files. The developer verifies each id from the installed app or a public listing, as in M1.5, and lists the unverified ones. `INSERT OR IGNORE` keeps a preset the user removed removed: a migration only adds ids that were never presets before.
- **Rollback:** an older build sees schema v5 as "made by a newer version" (the existing incompatible banner) and the `.bak` copy from the migration stays. No row is changed or deleted.

## How the source app is found

- **Mac** (in `ClipboardWatcher`, when the change count moves, before reading any text):
  1. If the pasteboard has the `org.nspasteboard.source` type (the nspasteboard.org convention many apps follow), its value is the source bundle id.
  2. Otherwise, the source is the frontmost app's bundle id (`NSWorkspace.shared.frontmostApplication`), read at the time of the poll.
  - Known limit: with polling every 250 ms, a copy followed by a switch to another app within 250 ms can be credited to the wrong app. A copy made by a background app (not frontmost) is credited to the front app. Secret markers still apply in both cases, and most password managers set them.
- **Windows** (on `WM_CLIPBOARDUPDATE`, before opening the clipboard to read):
  1. `GetClipboardOwner()` → `GetWindowThreadProcessId` → `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` → `QueryFullProcessImageNameW` → the exe file name, lower case.
  2. If there is no owner (some apps open the clipboard with no window), the foreground window's process is used instead.
  - If neither can be read (for example an elevated process that refuses), the source is "unknown" and the copy is captured as today. This fails open: the list can't be applied, but secret markers still are.

## Options

### A: The native watcher decides, before reading (recommended)

- Dart sends the ignore list and the pause state to the native clipboard watcher:
  - `setCaptureIgnored {appIds}`, the same ids `setIgnored` already sends to typed shortcuts;
  - `setCapturePause {until}`, where `until` is 0, -1 or the end time in ms.
- On each change, native code checks, in order:
  1. secret markers (as today);
  2. pause, comparing `until` with the wall clock now;
  3. the source app against the list.
- Each skip happens before the text is read. The text and the app id never reach Dart. The skip is logged as a code only.
- **Benefits:**
  - It works like the existing secret skip and like ADR 0004: what Kusunga mustn't keep, it never reads.
  - Pause is exact after sleep, because native code checks the wall clock on every change.
- **Costs:** the rule is written twice, in Swift and C++, each with unit tests. It also needs a small Dart port for the two calls. Effort: about 1.3× option B.

### B: Native sends the source app with each copy; Dart decides

- Each clipboard event gains an `appId` field, and Dart drops ignored or paused copies.
- **Benefits:** one copy of the rule, in Dart.
- **Costs:**
  - The text of an ignored copy is still read and crosses into Dart before it is dropped.
  - The app id of every copy crosses the channel, so a record of which app the user copied from now exists in the main app.
  - The pause check relies on a Dart timer, which can run late after sleep.

## Decision

Option **A**, recorded in ADR 0005 (accepted by the PM, 2026-11-10).

## Pause clock

- `PauseService` (Dart) holds `pausedUntil`. Pause and Resume write the setting, then call `setCapturePause`.
- Native code compares `until` with the wall clock on each copy, so capture stops and starts at the right moment even if Dart is late.
- The UI (banner, tray tooltip, tray menu) refreshes on a 15 s tick, when Kusunga becomes active, and on wake from sleep. When a timed pause has passed, Dart writes 0, so the banner never shows a time in the past for more than 15 s.
- If the clock is set back: at start-up and on each tick, a timed pause that ends more than 60 minutes from now is cut to now + 60 minutes. A pause never lasts longer than the user chose by more than a clock change.
- At start-up, the setting is read before the native watcher starts, so no copy slips in during launch while history is paused.

## Tray / menu bar

- When not paused, the menu reads:
  - Open picker
  - Open Kusunga
  - Pause history ▸
    - For 15 minutes
    - For 1 hour
    - Until I resume
  - Quit
- When paused, "Pause history ▸" is replaced by "Resume history".
- The tooltip reads "Kusunga — history paused until 14:30" or "Kusunga — history paused".
- When paused, the icon gets a paused variant: the same shape with a pause mark. The paused state is shown in the menu, not only by the icon.

## Failure plan

No outbound calls. Local failures:

- **The setting can't be written** (memory-only mode or a database error): the pause still applies for this session, in memory only. The Privacy tab says "Pause won't last after Kusunga quits." and the error is logged as a code.
- **Native call fails:** Dart keeps its state and retries once on the next tick. The status line shows "Couldn't apply the pause. Try again." while the state is out of step.
- **The source app can't be read:** see "How the source app is found". The copy is captured, as today.

## Observability

- New log codes: `captureSkippedIgnoredApp`, `capturePaused` (with the chosen length only: 15, 60 or until resumed), `captureResumed` (user or timer), `captureSourceUnknown` (Windows only, counted, no name).
- Nothing names an app or holds text.
- The number to watch in beta: how often `captureSourceUnknown` appears.

## Trust boundaries and abuse cases

- **Boundaries:**
  - The OS clipboard and its owner or source information, which any app can set.
  - The tray menu, which anyone at the computer can use.
- **Abuse cases:**
  - "As another app, I write the source marker of an ignored app, so that my copies aren't recorded." Gain: none for an attacker; this only reduces what Kusunga keeps.
  - "As malware, I copy a password with no secret marker while a password manager is in front, so that it lands in history." Mitigation: none needed. That is malware's own copy, and the user's real copies from the password manager are still skipped.
  - "As someone at the user's unlocked computer, I pause history so that the user's later copies aren't kept." Impact: data not kept, which is the private direction. The banner and tray tooltip make it visible.
  - "As someone at the user's unlocked computer, I remove a password manager from the list." Same exposure as M1.5; the full history is already readable by that person.
- **Residual risks** (stated, not mitigated, to be confirmed by QA):
  - On Mac, a copy from a password manager that sets no secret marker, followed by a switch to another app within 250 ms, can be recorded.
  - On Windows, a copy from an elevated password manager whose process name can't be read is recorded, unless it sets a secret marker.

## Privacy

Not legal advice. Items marked "PM decides" need the PM's decision before the developer starts.

| Field | Purpose | Lawful basis (PM decides) | Retention | Shared with | Notes |
|---|---|---|---|---|---|
| Source app of a copy (bundle id or exe name) | Decide whether to skip the copy | PM decides — likely n/a while nothing leaves the device (as plan D7) | Native memory only, for the time of one check (under 5 ms); never stored, logged or sent to Dart | None | Option A keeps it native |
| Ignored apps list (existing, M1.5) | Know which apps to skip | As above | Until the user removes an app | None | Encrypted file; can show which password manager the user has; export in M1.8 |
| `history_paused_until` | Keep the pause across a restart | As above | Until the pause ends or the user resumes; then 0 | None | Encrypted file |

- Fields removed: the app of each history item. It is not stored, although it would allow "copied from" labels (Later line).
- DPIA screening: no new trigger. This item reduces what Kusunga keeps. The keystroke DPIA is already planned in M1.9 (M1.5 D6) — no PM decision needed.
- Children likely: no — a desktop productivity tool.
- Automated decisions or profiling: none.
- Special category data: none new. The list can hint at the user's security tools, not at special categories.
- New vendors / SDKs / transfers: none. `tray_manager` is already in use.
- Private defaults:
  - the preset list is on;
  - after a restart the pause stays on if decision D3 is A;
  - Resume is one action.
- Export, delete, rectify: the list is edited in the app. Export of settings and lists is in M1.8. The pause setting is deleted with the data file.
- Record of processing and privacy notice: add "Kusunga checks which app a copy came from, on your computer only, to skip apps you chose; it doesn't record it" to the privacy notice in M1.9.
- Escalated to PM: lawful basis (likely n/a); D1–D5 below.

## Decisions for the PM

- **D1 — one ignore list or two?** A: one list for history and typed shortcuts (as M1.5 D4 planned). B: two separate lists. Recommendation: A, because an app you don't want recorded is almost always one where you don't want shortcuts either.
- **D2 — banking apps in the preset list?**
  - A: password managers only, adding the verified ones listed under Data. Banking in a browser is covered by secret markers and Pause, and a Later line covers banking app presets. The AC wording changes to "preset with common password managers".
  - B: also add banking apps now, from public listings.
  - Recommendation: A. Very few UK and EU banks have desktop apps, and their ids can't be checked here.
- **D3 — does a pause survive a restart?** A: yes, a timed pause continues to its end time and "until resumed" stays on. B: no, a restart resumes history. Recommendation: A, because a pause is a privacy choice and a restart shouldn't undo it quietly.
- **D4 — where in the app?**
  - A: a new third tab, "Privacy", in the main window, holding Pause history and the ignore list. The Typed shortcuts section keeps its switch and status, with a link to the list.
  - B: keep the list in the Snippets tab, and put Pause only in the tray and a History banner.
  - Recommendation: A, because the list now applies to history too, and M1.7 Settings can fold the tab in later.
- **D5 — on Mac, which app counts as the source?**
  - A: the app named in the pasteboard's source marker, when present, otherwise the front app.
  - B: always the front app.
  - Recommendation: A, because the marker is right even for background copies, and an app faking it only hides its own copies.

## Rollout and rollback

1. Schema v5 (new presets only), then `PauseService` and its setting, then the native skip on Mac, then Windows, then the tray menu, then the Privacy tab and the banner.
2. The pause defaults to off, and the list is the M1.5 list plus new presets, so there is no behaviour change until the user acts. The one exception is that copies from preset password managers stop being recorded at once, which is the AC.
3. Rollback: revert the merge. Schema v5 stays, and the older build shows the incompatible banner and keeps the `.bak` copy.
