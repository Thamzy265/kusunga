## Not observed
- Windows window and tray at runtime: no Windows machine; CI only builds and runs unit tests. Needs the PM on a real PC if wanted (optional).
- Physical Dock-icon click: replaced by `open` (same reopen event). Low risk.
- Light appearance of the real app: cannot be forced without changing system settings. Needs the PM (PM check 2, optional).
- Video: `screencapture -v` records the whole display and cannot be cropped to the app, so no video was recorded (it would capture the PM's desktop). Screenshots only.
- Live VoiceOver: not run; accessibility tree checked instead.
- Subjective look and feel: PM.

## PM check
Optional, about 3 minutes. Only things a tool could not do.

1. Switch your Mac to Light appearance (System Settings > Appearance), then start the app.
```bash
cd /Users/williamnasoni/Developer/Personal/kusunga && /Users/williamnasoni/Developer/flutter/bin/flutter run -d macos
```
Expected: a "Kusunga" window with readable text on a light background, and a "K" icon in the menu bar. If the window stays dark or the text is hard to read, tell the lead. Switch the appearance back afterwards.
2. Press `q` in the terminal to stop the app (or choose Quit from the menu-bar icon).
3. Windows (optional): on a Windows PC, run `flutter run -d windows` and check the same: window opens, tray icon appears, its menu has "Open Kusunga" and "Quit", closing the window keeps the icon, Quit removes it. Not required for the criterion beyond CI.

(These steps were not run by QA, because they need a system appearance change and a Windows PC; the rest of M1.1 was run by QA.)
