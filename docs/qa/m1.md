## M1.2 Clipboard history capture

Date: 2026-11-03 — Environment: macOS 27.0.1 (26A434), Flutter 3.44.6 / Dart 3.12.2, branch `feat/clipboard-history`, commit c8d4ebf (draft PR #2), debug build run with `flutter run -d macos --debug` (needed so the app could be inspected over its localhost VM service) and release build `build/macos/Build/Products/Release/Kusunga.app` run directly. CI run https://github.com/Thamzy265/kusunga/actions/runs/41655738313 (head c8d4ebf, macos and windows both `success`).

**Session conditions that limit this run (read first).**
1. The Mac screen was locked for the whole session (`CGSSessionScreenIsLocked = 1`). While locked, System Events sees no windows (`count of windows of process "Kusunga"` = 0), CGEvent input does not reach the app, and `screencapture -l` / ScreenCaptureKit fail ("could not create image from window", error -3811). So no OS-level clicks, hover, keystrokes or real-window screenshots were possible. Unlocking needs the PM's password, so QA did not try.
2. As a stand-in, the debug app's own VM service (127.0.0.1 only) was used: screenshots are Flutter's own render of the app (`ext.flutter.inspector.screenshot`; shows only the app, never the desktop), and the history service's state and methods were read and called in-process. Items marked "in-process" were not driven through the real UI. Injected pointer and key events were tried and did not reach the widgets (hover and arrow keys had no effect), so hover, focus and keyboard paths are NOT RUN.
3. The login-keychain prompt for this build was never answered (QA must not click it). In every launch (5 in this session, all logged `keychainTimeout`) the app went memory only after the 30 s timeout and showed the banner. Everything below that works in memory-only mode was run. Anything that needs the key (encryption, persistence, quit and relaunch) is NOT RUN, with a PM step below.

Acceptance criteria (docs/PLAN.md M1.2, copied):
- AC1: text and links copied in any app appear in history within 1 second.
- AC2: history keeps the newest N items; N is set in settings (default 200, range 10-5,000); the oldest item is removed when the limit is reached.
- AC3: duplicates move to the top instead of being saved twice.
- AC4: history is stored encrypted on disk, with the key in the OS keychain (Mac Keychain / Windows Credential Manager).
- AC5: items marked secret by password managers (Mac `org.nspasteboard.ConcealedType`/`TransientType`/`AutoGeneratedType`; Windows markers) are never saved.
- AC6: the user can delete one item (with Undo) and clear all history.
- AC7: if the keychain cannot be reached, history is kept in memory only with a warning and is never written unencrypted.
